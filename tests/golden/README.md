# Golden fixtures

Expectations in this directory were **generated by the Ruby implementation**, not
written by hand. Whatever the Ruby build of wip produced became the contract the C#
port has to meet, so a difference is a real behavioural change rather than a
disagreement between two people's readings of the spec.

They were produced by:

```
ruby tools/golden/generate.rb        # tests/golden/cases/**/cases.json
ruby tools/golden/generate_units.rb  # tests/golden/units/*.json
```

Both scripts, and the Ruby implementation they import, leave this repository once the
port lands (see `docs/csharp-migration-plan.md`, Phase 1). After that the JSON is the
only surviving record of the old behaviour, which is the point — it has to be captured
before the source of truth goes away.

## Layout

| Path | What it pins |
|---|---|
| `cases/<fixture>/wip.yml` | Input config, plus `.env` / `compose.yml` / `stack.yml` where relevant |
| `cases/<fixture>/cases.json` | ~320 operations: every `CommandBuilder` entry point, `Config#to_h`, dependency and command lookups |
| `units/shellwords.json` | `Shellwords.split` — no BCL equivalent, so the port hand-writes it |
| `units/variable_interpolation.json` | Compose `${VAR}` substitution |
| `units/dockerignore.json` | `.dockerignore` matching and walk pruning |
| `units/error_interpreter.json` | Raw wslc output to user-facing hint |
| `units/command_display.json` | Debug rendering, including `-e KEY=value` masking |
| `units/yaml_merge_keys.json` | `<<` merge keys, and the order-sensitive precedence Psych gave them |

Each operation records either `{"ok": <value>}` or `{"error": "<message>"}`. **Error
messages are part of the contract**: they are what a user sees when their `wip.yml` is
wrong, and regressing them regresses the tool.

## Absolute paths

Paths are rewritten to `<FIXTURE>` so the corpus does not depend on the checkout
location. The C# side substitutes the fixture directory back in before comparing.

## Deliberate divergence

The migration allows breaking changes, so some expectations are *meant* to change. Those
are the host-path-bearing ones, and they change because the process now runs on the
Windows side rather than inside WSL — see `docs/csharp-migration-plan.md` §3:

- `config.sync.to_h` → `source`
- `builder.sync_run`, `builder.sync_exec` → the `-v` source mount
- `builder.up`, `builder.run`, `builder.custom[*]` → `-v` entries derived from `volumes:`
- `config.compose_build_specs` → `context`

When one of these changes, update the expectation in the same commit as the code and say
why. Everything else should stay green untouched; an unexplained diff outside this list
is a regression.
